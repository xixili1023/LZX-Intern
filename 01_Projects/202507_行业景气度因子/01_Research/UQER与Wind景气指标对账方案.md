# UQER 与 Wind 行业景气指标对账方案

## 目标

本次对账要回答两个不同问题，不能合并成一句“数据是否一致”：

1. **数据是否同口径**：UQER 指标是否与原 Wind EDB 指标描述同一统计对象、口径、地区、频率和单位。
2. **研究上是否可替代**：即使数值并非逐点相同，UQER 指标经相同的时点控制和转换后，是否能提供方向、稳定性和行业收益解释能力相近的景气信号。

只有先通过数据层验证，才进入因子层验证。名称相似不能直接视为替代关系。

## 现有 Wind 基线

- 指标清单有效部分有 330 行、318 个唯一 Wind 代码和 28 个有效行业；原工作簿尾部另有 3 行空白或乱码行，需要在导入时丢弃。
- 数值宽表覆盖 `2015-01-01` 至 `2025-07-02`，包含 296 条序列和 2,740 个非周末日期，整体缺失率约 7.66%。
- 5 条数值序列在清单中缺少元数据，27 个清单指标在数值表中缺失。
- 原数值表已经按日期向后填充，且没有独立 `publishDate`。当前只能把列值首次发生变化的日期近似视作更新事件；当新一期公布值恰好等于上一期时，该方法会漏掉更新。

因此，Wind 宽表可以作为历史研究输入和数值参照，但不能单独证明严格的历史可得性。

## UQER 原始字段的职责

| 字段 | 含义 | 对账用途 |
| --- | --- | --- |
| `indicID` | UQER 指标主键 | 与人工映射表关联，不按名称临时匹配 |
| `periodDate` | 指标所描述的统计期 | 同口径数值对账的主时间键 |
| `publishDate` | 数据发布时间 | 决定回测中最早可用日 |
| `dataValue` | 原始数值 | 完成单位换算后与 Wind 对账 |
| `updateTime` | 数据库更新时间 | 识别修订和本次数据库入库时间；不能直接替代首次发布日期 |

元数据中的 `frequency`、`unit`、`statType`、`region`、`country`、`currency`、`infoSource`、`beginDate`、`endDate` 和 `isUpdate` 必须随原始数值一并保存。

## 2026-08-07 样本验证更新

- 24 个启用 API 已完成真实抽样，48 次请求零失败，共得到 26 行元数据和 2,786 行观测。
- 2,786 行观测中有 760 行缺失 `publishDate`，因此不能假设所有 UQER 指标都可直接构造 point-in-time 序列。
- `EcoInfoProGet.dataApiName` 的实际值是 `getEcoData...`，与数值调用的 `EcoData...Get` 不同；下载器已分开配置。
- 化工 API 的元数据约有 93,979 行，已经验证不应将“发现全部指标”与“下载全部历史数值”直接连接。

## 映射状态

每个 `Wind 指标 × 行业` 映射到 UQER 后，只能使用以下状态：

- `exact`：统计对象、定义、地区、频率、单位、调整方式和来源均一致。
- `near`：经济含义接近但至少一项口径不同；只能作为替代候选，必须单独做因子稳定性验证。
- `unavailable`：UQER 中未找到可接受的对应或替代指标。
- `pending`：元数据不足或存在多个候选，等待人工核对。

建议映射表至少记录：Wind/UQER 代码和名称、API、行业、统计对象、统计定义、频率、单位、地区、来源、季调/累计口径、单位换算、匹配状态、人工复核状态和备注。

## 三层验证

### 第一层：元数据同口径检查

逐项核对：

1. 统计对象是否相同，例如“天然气产量”不能与“表观消费量”混用。
2. 当期值、累计值、同比、环比、比率、价格和指数口径是否相同。
3. 地区、品种、市场、币种、价格类型和数据来源是否相同。
4. 日、周、月、季频是否相同，月度值的统计期定义是否一致。
5. 单位是否只存在可解释的倍率差，例如元/吨与万元/吨。
6. 是否季调、是否名义值/实际值、是否含税、是否为初值或修订值。

任何关键维度不明时先标记 `pending`，不进入自动拼接。

### 第二层：原始数值与可用时点检查

在重叠区间中保留原始更新频率，不先转为日频：

1. 用 `periodDate` 对齐同一统计期，先执行明确记录的单位换算，再计算重叠期、缺口、绝对误差、相对误差、Pearson/Spearman 相关和变化方向一致率。
2. 检查是否存在稳定的 10、100、1,000 倍或常数偏移；若有，必须回到单位和定义解释，不能只用回归结果自动修正。
3. 对数值不完全相同的日期检查初值/修订值、舍入精度、节假日归属和统计期错位。
4. 用 `publishDate` 构造 UQER 的历史可用序列；`updateTime` 仅用于识别数据库修订或入库变化。
5. 将 UQER 可用序列向交易日展开后，再与原 Wind 日频宽表比较首次变化日、缺失区间和滞后天数。

“完全一致”的判断应接近逐点相等并能由舍入误差解释；“近似替代”没有通用数值阈值，需结合指标类型、样本长度和后续因子结果确定，不预设一个对所有指标都适用的相关系数门槛。

### 第三层：因子可替代性检查

对 `exact` 和 `near` 分开评价，在共同样本期使用相同的转换、滞后、标准化和未来行业收益标签：

1. 比较处理后信号的覆盖率、相关性、方向一致率和极端期差异。
2. 分别计算 TS-IC、滚动 IC、ICIR、衰减和分行业稳定性。
3. 比较指标筛选结论、方向符号和行业内等权聚合后的景气度分数。
4. 在相同参数下比较纯景气度基线的收益、回撤、换手和行业暴露。
5. 分别报告“完全匹配”“近似替代”“缺失指标”对最终结果的贡献，不把替代后的结果冒充原 Wind 结果复现。

## 推荐执行顺序

1. 已完成接口样例下载和真实字段检查。
2. 只对与旧 Wind 指标相关的 API 下载元数据，固定候选元数据快照，不下载全部观测。
3. 依据元数据建立 Wind–UQER 人工映射表，并复核可疑重复接口。
4. 使用 `selected` 模式只下载已审核映射的重叠区间，完成第二层数值与时点对账。
5. 冻结映射表版本后下载已选指标的全历史数据，再做转换和日频展开。
6. 完成第三层因子可替代性实验，结果写入实验日志。

## 当前已识别风险

- 用户提供的接口清单中，“信息服务/轻工制造”“有色金属/综合”“公用事业/行业财务”各自共享完全相同的 API 和样例代码，至少有一侧可能错标。
- `isUpdate=1` 适合找持续更新指标，但会漏掉已停止更新、却对历史复现有价值的序列。全量元数据盘点时不能只保留持续更新项。
- 原 Wind 宽表缺少首次发布日期和修订版本，无法仅靠该文件做严格 point-in-time 复原。
- UQER 当前返回的历史值可能是修订后终值；需判断接口能否提供历史版本，否则要把修订风险列为研究限制。
- 申万 2014 与 2021 行业分类存在变更；指标行业映射与收益标签必须使用同一时期有效的行业口径。
- 数据许可和下载流量属于数据工程约束；原始受限数据、网关地址和密钥不得进入 Git。
