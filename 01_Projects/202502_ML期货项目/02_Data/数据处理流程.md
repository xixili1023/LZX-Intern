# 数据处理流程

## 1. 数据获取

通过 FastBox 查询 `CU2311` 基本信息，并读取 2023-10-16 至 2023-10-31 的 Level-2 快照。

## 2. 时间轴和缺失处理

- 以 500 毫秒构造完整时间索引。
- 保留日盘与夜盘的指定交易时段。
- 重建索引后使用前值填充。
- 删除仍为空的记录。

## 3. 重复和异常处理

- 按 `trade_time` 排序并删除重复时间戳。
- 当 `vol == 0` 时，将 `avg_price` 设为 `last_price`。
- 将高于涨停或低于跌停的价格字段设为缺失。
- 代码中将 `avg_price` 除以 5，具体口径待确认。

## 4. 特征构造

依次生成盘口深度、价差、订单不平衡、市场压力、SOIR、有效价差、多档 OFI 和 Hurst 等特征。详细定义见 [[../03_Factors/README|Factors]]。

## 5. 日内筛选与标准化

- 增加日期和小时字段。
- 仅保留 8:00–16:00 范围内的数据。
- 每个交易日内使用扩展窗口均值和标准差进行标准化。
- 删除初始窗口并将剩余缺失值填为 0。

## 6. 标签与划分

代码按日使用：

$$
return_t=\frac{last\_price_{t+6}}{last\_price_t}-1
$$

在半秒频率下对应未来 3 秒。最后两个交易日作为测试集，其余日期作为训练集。

## 7. 输出

- `Train_data.pkl`
- `Test_data.pkl`

`features.pkl` 来源于已有数据处理流程。当前 Notebook 从该文件继续生成标准化后的 `Train_data.pkl` 和 `Test_data.pkl`。

## 质量与偏差检查

- 已确认训练目标为未来 3 秒 `last_price return`。
- `last_price` 本身被模型特征切片排除，但 `D_k`、`effective_spread` 及部分 `avg_price` 记录依赖当前成交价。
- 订单簿中的 `last_price` 依赖当前时刻成交结果；相对于仅使用盘口形成信号的决策时点，它属于包含未来成交信息的价格变量，可能导致模型提前获得未来信息。
- 应确认前值填充没有跨越非交易日期或交易时段。
- 应确认所有特征只使用信号时点可获得的信息。
- 应避免随机验证划分造成时序泄漏。
- 应记录原始数据版本与生成日期。
