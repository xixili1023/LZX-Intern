# 项目数据库

本页由 Dataview 自动读取 `01_Projects/*/PROJECT_STATUS.md` 的 YAML metadata。项目状态只在各项目的 `PROJECT_STATUS.md` 维护，本页不重复手工录入。

## 项目列表

```dataview
TABLE WITHOUT ID
  link(file.folder + "/README", regexreplace(file.folder, "^01_Projects/", "")) AS "项目",
  project_status AS "状态",
  current_stage AS "当前阶段",
  project_type AS "项目类型",
  frequency AS "研究频率",
  method AS "主要方法"
FROM "01_Projects"
WHERE file.name = "PROJECT_STATUS"
SORT file.folder ASC
```

## Metadata 规范

每个项目在 `PROJECT_STATUS.md` 顶部维护：

```yaml
---
project_status: "规划中"
current_stage: "研究设计"
project_type: "因子研究"
frequency: "日频"
method: "因子构建"
---
```

字段约定：

| 字段 | 含义 | 建议值 |
| --- | --- | --- |
| `project_status` | 项目整体状态 | `规划中`、`进行中`、`暂停`、`已完成`、`已归档` |
| `current_stage` | 当前研究阶段 | `研究设计`、`数据处理`、`因子测试`、`模型训练`、`回测验证`、`报告整理`、`已完成` |
| `project_type` | 主要研究类型 | `因子研究`、`策略回测`、`机器学习`、`数据研究` |
| `frequency` | 最终研究、信号或回测的主要频率 | `高频`、`日频`、`周频`、`月频` |
| `method` | 项目的主要研究方法，只选最能代表项目的一项 | `因子构建`、`机器学习`、`LightGBM`、`组合优化`、`回测` |

项目名称直接来自项目目录名；创建月份直接来自 `YYYYMM_项目名称` 的目录前缀，因此不再重复建立属性。

`frequency` 记录最终研究、信号或回测的主频率，不记录每个原始数据源的频率。`method` 只填写一种主要方法；具体模型和辅助方法继续写在研究文档中。

## 最小标签规则

Tags 不是必填属性。只有同时满足下面三个条件才添加：

1. 目录和 `project_type` 无法表达这个主题；
2. 至少有两个项目共享这个主题；
3. 确实需要跨项目搜索这个主题。

当前只有两个研究方向不同的项目，没有形成实际的跨项目标签需求，因此暂不使用任何项目标签。

以下标签全部不使用：

- `quant-research`：整个仓库已经是量化研究；
- `factor-research`、`machine-learning`：已经由 `project_type` 表达；
- `home`、`project-database`、`experiment`：已经由目录和文件位置表达；
- `task`：Tasks 根据复选框识别任务，不需要标签。

新增项目默认不加标签。以后出现多个项目共享同一主题时，再给相关项目增加同一个标签，每个项目最多两个。

> [!important]
> Dataview 只负责读取和展示。修改项目状态时，应编辑对应项目的 `PROJECT_STATUS.md`，不要修改查询结果。
