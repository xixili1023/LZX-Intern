# Quant Research Configuration

本文件定义 Personal Quant Research Portfolio 的工作空间级量化研究规范。规则适用于量化投资、因子研究和策略回测，不包含任何具体项目内容。

## 1. Workspace

- Home：`00_Home`
- 项目根目录：`01_Projects`
- 公共数据：`~/Desktop/InternData/StockData`
- 项目专属数据：`~/Desktop/InternData/<项目数据目录>`
- 公共代码：`02_Assets/Code`
- 公共参考资料：`02_Assets/References`
- 模板目录：`03_Templates`
- 学习资料：`04_Learning`
- 项目输出：`01_Projects/<Project_Name>/07_Report`

项目专属研究、数据说明、代码、实验和报告留在项目内；只有具备跨项目复用价值的资产才进入 `02_Assets`。

## 2. Templates

- 项目模板：`03_Templates/Project_Template`
- 因子模板：`03_Templates/Factor_Template`
- 回测模板：`03_Templates/Backtest_Template`
- 研究报告模板：`03_Templates/Research_Report_Template`

模板只作为复制来源，不直接填写具体研究内容。

## 3. 代码规范

### 3.1 目录与职责

- 项目代码统一保存在项目的 `05_Code`。
- 数据处理、因子、模型、回测和工具代码分别进入对应模块。
- 跨项目通用且稳定的代码进入 `02_Assets/Code`。
- 研究逻辑记录在 Markdown 文档中，不以代码替代方法说明。

### 3.2 命名与风格

- 文件、目录、函数和变量名称应表达职责，避免含糊缩写。
- Python 文件、函数和变量使用 `snake_case`；类使用 `PascalCase`；常量使用 `UPPER_SNAKE_CASE`。
- 配置项、数据字段和指标名称在同一项目中保持一致。
- 注释解释原因、假设和边界，不重复描述代码表面行为。

### 3.3 可复现与质量

- 不在代码中硬编码密钥、本地绝对路径或个人环境信息。
- 参数与代码分离；关键参数必须能够被记录和复用。
- 随机过程固定随机种子，并记录运行环境和依赖版本。
- 重要数据处理、因子计算和回测逻辑应具备可验证的检查。
- 修改核心逻辑时同步更新相关研究文档、实验记录和报告。
- Git commit 应保持单一目的，并使用能够说明变更内容的提交信息。

## 4. 数据规范

### 4.1 数据分层

- `raw`：保存未经修改的原始数据或其本地入口。
- `processed`：保存通过可复现流程生成的研究数据。
- 公共数据进入仓库外的 `~/Desktop/InternData/StockData`；项目专属数据进入仓库外的 `~/Desktop/InternData/<项目数据目录>`。
- 原始数据视为不可变输入，不直接覆盖或人工修改。

### 4.2 数据说明

每项数据资源至少记录：

- 数据来源、获取方式和使用许可
- 数据版本、获取日期和覆盖范围
- 更新频率、字段定义、单位和主键
- 时区、交易日口径和信息可用时间
- 缺失值、异常值、重复值和质量检查
- 清洗、转换、复权、对齐和重建步骤
- 已知限制及潜在偏差

### 4.3 存储与安全

- 不向 Git 提交大型原始数据、敏感数据、访问凭证或受限数据。
- Git 跟踪数据说明、字段字典、小型样例、配置和重建流程。
- 不将缓存、临时导出文件或可重建的中间产物作为正式数据。
- 所有人工修正必须记录原因、时间、范围和处理方式。
- 数据产物应具备稳定的版本标识或可复现快照标识。

## 5. 日期规范

### 5.1 日期格式

- 普通日期统一使用 ISO 8601：`YYYY-MM-DD`。
- 月份使用 `YYYY-MM`；年份使用四位数 `YYYY`。
- 时间戳使用 ISO 8601，并明确时区，例如 `YYYY-MM-DDTHH:mm:ss+08:00`。
- 文件名需要日期时使用 `YYYY-MM-DD`，不使用含义不清的纯数字日期。

### 5.2 研究时间口径

- 明确区分自然日、交易日、报告期、公告日、发布日期和数据可用日。
- 明确样本区间是否包含开始日和结束日。
- 日频及更高频数据必须记录时区和交易时段。
- 月度、季度和年度数据应说明期末值、区间累计值或发布日期口径。
- 回测只能使用决策时点已经公开且可获得的信息。
- 跨市场研究必须先统一或明确各市场时区、交易日历和节假日差异。

## 6. 股票代码规范

### 6.1 标准格式

- 股票代码一律作为字符串保存，禁止转换为会丢失前导零的数值类型。
- Portfolio 内部标准格式使用 `<symbol>.<exchange>`。
- 中国内地交易所后缀统一为：
  - 上海证券交易所：`.SH`
  - 深圳证券交易所：`.SZ`
  - 北京证券交易所：`.BJ`
- 其他市场应在项目数据说明中定义唯一、稳定的交易所后缀。

### 6.2 映射与历史

- 数据接入层负责将供应商代码映射为内部标准代码。
- 保留原始供应商代码，并记录映射规则和供应商名称。
- 不在不同数据源之间依赖模糊的代码字符串拼接。
- 股票简称只用于展示，不作为唯一标识或连接主键。
- 退市、转板、代码变更和证券类型变化应保留历史映射。
- 涉及同一代码跨时期复用时，应使用稳定证券标识辅助区分。

## 7. 回测规范

### 7.1 基本定义

每次正式回测必须明确：

- 研究假设、策略规则和适用范围
- 资产池、样本期、基准和数据版本
- 信号生成时间、信息可用时间和订单执行时间
- 调仓频率、权重规则、持仓限制和风险约束
- 手续费、滑点、冲击成本、流动性和不可交易状态
- 绩效指标、风险指标、对照方案和稳健性检验

### 7.2 偏差控制

- 禁止使用决策时点尚不可得的信息。
- 检查前视偏差、生存者偏差、选择偏差、数据泄漏和过拟合。
- 保留退市证券、停牌、涨跌停和无法成交等现实状态的处理说明。
- 参数调整、样本筛选和策略规则变更必须记录，不得静默修改。
- 不只保留成功实验；失败和不利结果同样进入实验记录。
- 区分样本内与样本外、毛收益与净收益、绝对表现与基准比较。

### 7.3 实验追踪

每次正式运行至少记录：

- Experiment ID
- Date
- Git commit
- Data version
- Strategy or factor version
- Parameters
- Metrics
- Artifact location
- Conclusion and limitations

历史回测结果不得表述为未来收益保证。

## 8. 报告规范

### 8.1 存放位置

- 项目报告、实习汇报、面试材料和展示版本统一保存在项目的 `07_Report`。
- 不创建独立的顶层报告目录。
- 报告模板只从 `03_Templates` 复制，不在模板目录中填写项目内容。

### 8.2 内容要求

报告应根据用途包含：

- 项目背景、研究问题和个人贡献
- 数据来源、样本范围和关键口径
- 因子、模型或策略逻辑
- 回测框架、参数、成本和偏差控制
- 实验结果、稳健性检查和基准比较
- 风险、局限、失败结果和后续方向
- Git commit、数据版本、实验 ID 和复现入口
- 参考资料与 `[[双向链接]]`

### 8.3 表达要求

- 事实、用户陈述、推断、假设和结论必须清晰区分。
- 所有关键指标和结论必须能够回溯到项目证据。
- 不虚构结果、引用、职责、影响或项目经历。
- 不隐瞒关键限制、失败实验或不利结果。
- 针对完整研究、实习汇报和面试讲解调整篇幅，但保持事实口径一致。
- Markdown 文档应同时保持 Obsidian 导航能力和 GitHub 可读性。
- 对外材料不得暴露密钥、敏感数据、隐私或保密信息。

## 9. 规范优先级

1. 用户在当前任务中的明确要求
2. 本文件的工作空间级规范
3. 项目 README 与项目内明确记录的约定
4. 模板默认约定

项目确需偏离本规范时，应在项目文档中记录偏离原因、适用范围和影响。
