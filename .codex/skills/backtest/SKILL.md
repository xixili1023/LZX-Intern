# Backtest

## 使用场景

- 为量化投资策略或因子策略设计标准回测框架。
- 完善回测参数、交易规则、组合构建和绩效评价说明。
- 审查已有回测是否存在时间错位、偏差、成本遗漏或不可复现问题。
- 将正式回测运行纳入实验记录并关联 Git 与数据版本。
- 为项目报告整理可核验的回测证据。

## 输入要求

开始前确认：

- 研究问题、信号或策略规则及其预期机制。
- 资产池、样本期、基准、频率和数据版本。
- 信号生成时间、信息可用时间、执行时间和调仓规则。
- 组合构建、权重、持仓限制、风险约束和现金处理。
- 手续费、滑点、冲击成本、流动性与交易限制。
- 评价指标、对照方案、稳健性检验和已有实验记录。

若关键时间口径或交易假设不明确，应先停止执行并列出缺口。

重要回测实验必须同步记录到 `06_Experiment/experiment_log.md`，至少包含：

- Experiment ID
- 实验目的
- 研究假设
- 参数设置
- 数据范围
- 结果指标
- 实验结论

## 执行流程

1. 检查 `01_Research`、`02_Data`、`03_Factors`、`04_Backtest`、`05_Code/backtest` 和 `06_Experiment`。
2. 固定资产池、样本范围、基准、数据版本和信号版本。
3. 明确信号计算、组合形成、订单执行和持仓更新的时间顺序。
4. 定义权重、再平衡、风险控制、交易成本和不可交易状态处理。
5. 检查前视、生存者、选择、数据泄漏、过拟合和重复试验偏差。
6. 设计收益、风险、回撤、换手、成本和稳定性评价。
7. 将重要回测实验写入 `06_Experiment/experiment_log.md`，记录实验 ID、目的、假设、参数、数据范围、结果指标和结论。
8. 将实验记录关联对应 Git commit、数据版本和必要的小型结果文件。
9. 保留失败与不利结果，比较基准和稳健性方案。
10. 将可复现结论和限制链接到 `07_Report`。

## 输出要求

- 输出回测框架、参数表、交易假设和偏差控制说明。
- 每个重要结果均能追溯到 `experiment_log.md`、代码版本、研究文档、配置、数据范围和结果文件。
- 区分毛收益与净收益、样本内与样本外、基准比较与绝对表现。
- 汇报结果产物位置、验证状态、异常、限制和待补检查。

## 注意事项

- 未经用户明确要求不运行回测。
- 不虚构绩效指标，不推断不存在的结果。
- 不覆盖既有结果；使用可追踪的实验 ID 或版本。
- Git 负责代码、研究文档、配置文件以及必要小型结果文件的版本管理；实验目的、过程和结论仍由 `experiment_log.md` 维护。
- 不省略交易成本、执行延迟和现实交易约束。
- 不将历史回测表现表述为未来收益保证。
- 不为提升表现而静默调整参数、样本或策略规则。
